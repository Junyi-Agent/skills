# 被唤醒时

agent 只有被唤醒才会动。说了「接下来会做 X」就结束这一轮，下一轮什么时候来没有保证，X 就没人做。

## 条款

被唤醒时，如果消息里有派给自己的活，必须在同一轮内开工。不开工的话，在回复里写一行：

```
不开工原因：<在等什么、等谁>
```

例如在等某人确认方案、缺权限、要用的东西还没合并。只写「接下来会做 X」「下一步 X」，不算开工，也不算写了原因。

## 怎么做

1. 先把消息里派给自己的活列出来，每条写一句。
2. 每一条要么在这一轮开始做（跑命令、改代码、开 PR、开 issue），要么写一行「不开工原因：…」。
3. 回复消息，汇报做到哪；接着做，或者结束这一轮。

只回一句「收到，马上做」就结束，是这条条款要防的情况。

## 用 IM 工具回复

回复要用 IM 工具（send_message / send_dm）发出去。只写在这一轮最终文本里的话，对方收不到通知，要靠系统代贴。确实不需要回复（例如对方只是确认收到）时，在最终文本里写一行：

```
无需回复：<原因>
```

## 发给谁、要不要 @

- 只给自己的 +1 看的内容（汇报、提问、确认）走私聊，不发到群里。项目组只有你和 +1 两个人时，群里只回老板或别人直接 @ 你的消息。
- 确认、致谢这类没有新信息的消息不发；要发也不 @ 人。每次 @ 都会唤醒对方，消耗对方的额度，互相 @ 会把双方的额度用完。

## 向上要决策

需要上级或老板定方向时：

1. 把每个问题写成选项（A / B / C），对方回字母就能定；有不能选项化的，写清楚要对方给什么（日期、清单）。
2. 所有问题一次问完，不分几轮追问。
3. 等答复的同时，先做不受这些决定影响的事，并在消息里写明在做什么。

## 自动检查

`scripts/wake_guard.py` 是 Claude Code 的 Stop hook，结束一轮时检查：这一轮是被唤醒的；除了 IM、加载 skill、读文件、HANDOFF.md 之外没调用别的工具；回复里有「接下来 / 下一步 / 准备」这类承诺；却没有「不开工原因：」。四条都满足，就不让这一轮结束，并提示开工或者写明原因。

它还检查这一轮有没有调用 `mcp__im__send_*`：没有调用，最终文本里也没有「无需回复：」，就不让这一轮结束，提示用 IM 工具回复。

在 `.claude/settings.json` 里配置：

```json
{"hooks": {"Stop": [{"hooks": [{"type": "command", "command": "<本 skill 目录>/scripts/wake_guard.py"}]}]}}
```

已知缺口：承诺的说法靠匹配词判断，会漏判，也会误判。跑一条与 HANDOFF.md 无关的命令（哪怕是只读的）就算开工。这个 hook 只挡住「明显只回复」的情况，派下来的活有没有做完，它管不了。回复发给了谁、该不该 @，它也不查。
